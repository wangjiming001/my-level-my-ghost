# 参考游戏关卡蒸馏

用户确定黑色椭圆头火柴人为本项目主角。保留角色身份、固定全图视角，角色比例可按用户要求校准。

1. **先实测再设计。** 确定版本、入口及关卡范围，正常速度操作并录制关键过程。每关记录房间边界、人物起点、出口、地形、机关位置，触发前后人物的位置与动作，以及同关多个机关如何关联。记录玩家的预期、行动、反转与知情后的解法，也检查相邻关卡怎样建立和打破习惯。
2. **测比例和时间。** 以地图单位和人物为参照，测可见轮廓、坑宽、房间宽高、跑速、起跳和落地位置、跳跃时间、机关变化速度及相对领先量；注明采样帧、时间戳、方法、误差与掉帧。对短按/长按和不同路线进行对照。
3. **分清证据。** 可见图片、碰撞盒、支撑判定、触发条件和源码参数是不同对象。只有画面时，碰撞盒和触发公式标为推测，未测量的数据标未知；不宣称逐帧复刻或100%还原。把来源、证据与推断写入研究记录。
4. **形成可复用规则。** 用与人物碰撞盒、地形宽度、速度及时间相关的参数表达触发和移动，明确单位、边界、顺序与复位；不把某个画面像素或固定关卡坐标冒充通用规律。通过改变起点、机关和出口的位置检验复用。机制和参数以当前引擎能力为准，不能声称尚未实现的功能已支持。
5. **生成我们的关卡。** 保留“意想不到、规律固定、知道后可通过”的体验，先设计玩家为何相信、如何行动、哪一刻被反转；关联机关前后配合，知情解法靠理解而不是像素精度。参考设计规律，制作自己的地图与表现。
6. **成对验证。** 对同一版本分别检查自然盲走、看到变化后才反应、提前知情跳跃、多组合理操作时机、重试复位、视觉与碰撞对应、完整跑通；追赶关验证短暂停顿恢复、其他机关不强行套用追赶标准。机器模拟通过不等于好玩，交付手机预览供用户试玩。
7. **兼容与交付。** 物理变化采用新快照版本，旧影子、克隆和分享按原版本回放，完整评论JSON不超过2048 UTF-8字节。遵守项目测试要求；区分浏览器模拟和手机实测。用户授权预览不代表送审或发布。

## v12 跑速候选与推广限制

隔离实验位于 `experiments/speed-v12/`，用 `node experiments/speed-v12/validate.cjs` 复跑。候选规则为角色满速86单位/tick、约5.039坑宽/秒，接近录像估计5.02–5.17；追赶边缘按1.5倍计算，移动坑109单位/tick。触发距离随实际速度计算，版本标记为12，旧v11回放仍按旧速度。碰撞盒保持原值，原作碰撞盒未测得，不得声称碰撞一致。

当前候选仅五个示范关及平移布局的模拟路线通过；落石组合中的v11知情路线在高速下会在落稳前提前触发并死亡。虽然找到个别触发后通关路线，稳定的非精确操作余量还未证实；不得把候选视作全机关通用、推广到玩家关或作为已通过最终验证。要复用到每种新机关，先按不同速度、起跳/落地、提前触发和停止距离配对测盲冲与宽余量知情路线，验证旧快照、目标平台与手机体验。
