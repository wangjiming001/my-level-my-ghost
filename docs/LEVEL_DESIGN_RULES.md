| 对象 | 当前触发与效果 | 限制/入口 |
| --- | --- | --- |
| 固定尖刺 SPK | 玩家碰撞盒接触刺的伤害区即死亡 | 编辑器可放；不是整格都致命 |
| 塌陷地板 COL | 站上地板后开始倒计时；v6 参数 4 tick（旧版 14），按现有同帧递减顺序执行，归零后失去碰撞 | 引擎有实现；编辑器未开放；v10 示范关使用 |

| 弹跳台 TRM | 向下碰撞台面且上一 tick 未接地时施加向上速度 | 编辑器可放；平地横向走入不会直接起弹 |
| 移坑 SHIFT | v8附近起跳后向右移1格追落点；v7旧快照仍向左 | 当前v8示范关；无编辑器画笔 |
| 扩张坑 CHASE | 先取得领先，再以跑速1.5倍向右追赶，保留出口平台 | v8；先跳再跑，量化短暂停顿验收 |
| 起点 ST / 终点 GL | 起点初始化角色；触碰终点有效区域即胜利 | 目前固定位置，不会移动或假装通关 |

当前地图 12×8，含空格共 11 种 tile；每格编码 4 bit。地图结构校验要求一个起点、一个终点；COL/HID/FALL 合计最多 3 个，SPK/TRM 不计入这 3 个。当前录制上限 1200 tick（60 tick/s，20 秒）。

现有数据版本 v8，支持按原规则读取 v2/v3/v4/v5/v6/v7；物理与回放都必须按现有规则执行。不得因为本文列出新机制，就让生成器输出尚不支持的对象或字段。

## 3. 需要学习的机关类型

“参考中存在”仅指资料描述；本项目采用何种触发方式另行明确。

| 类别 | 参考中存在的表现 | 本项目拟采用的规则 | 状态 |
| --- | --- | --- | --- |
| 地形失效 | 地面打开或消失 | 踩踏/边缘试探 → 快速失去碰撞 | COL 已有；扩展未实现 |
| 危险物移动 | 刺、锯片改变位置或方向 | 进入指定区域 → 沿固定轴移动 → 到边界停止/回返 | 未实现，无锯片素材 |
| 上方袭击 | 上方障碍压下 | 进入安全引发边缘 → 快速下砸 → 落稳 | FALL 已有；广域压顶未实现 |
| 落点变化 | 平台落地后移动 | 首次落地 → 延迟 → 平台平移，携带角色的规则须单独定义 | 未实现 |
| 出口反转 | 本项目拟设计为接近出口后出口移位 | 接近但尚未触发胜利 → 出口沿预设路径移动一次；始终保留可达真终点 | 原创候选，未实现 |
| 输入反转 | 左右操作翻转 | 进入区域 → 显示反向提示 → 区域内交换左右输入 | 未实现；UI 按钮位置不变 |
| 跳跃变化 | 跳跃高度变化 | 进入区域后采用一组固定跳跃参数，离开恢复 | 未实现 |
| 重力反转 | 重力方向翻转 | 触发开关后切换重力；碰撞、接地、跳跃、终点均需适配 | 未实现，后置 |
| 诱饵 | 金币用途发生变化 | 可选奖励诱导绕路；危险由明确的机关协议触发 | 未实现，无金币素材 |
| 传送 | 传送后落到危险处 | 碰触入口 → 传送至预设有效位置 → 退出需重新进入才能再触发 | 未实现，无传送门素材 |
| 玩家触发机关 | 本地双人主动坑对方 | 暂不引入实时对战；改由创作者布置、挑战者离线触发 | 不纳入首轮 |

素材与能力分开检查：引擎可模拟不等于已有美术；已有图片不等于具备物理行为。

## 4. 统一触发协议（拟议，尚未接入快照）

将“什么时候动”与“动什么”拆开，避免每新增一个道具就硬编码一套关卡。

触发器候选：
- enter_region：玩家碰撞盒从区域外进入区域内，边沿触发；不能每 tick 重触发。
- step_on：本 tick 从非支撑该对象变为支撑该对象。
- leave_support：玩家离开指定支撑物；可用于离开后切断退路。
- jump_start：角色实际执行起跳，不是持续按住跳键；绑定指定区域。
- land_on：角色从空中下落并接触指定表面。
- hit_underside：向上运动时碰到对象底部。
- touch：碰撞盒首次与指定对象相交。
- elapsed_ticks：从本轮开始或上一个事件起经过固定 tick。
- action_complete：指定机关完成动作后启动下一个机关；引用必须存在。

动作候选：出现、消失、变为致命、沿轴移动、落下、反向、切换输入规则、切换物理参数、移位终点。

每个机关至少明确：唯一 ID、对象与初始状态、触发器、触发区域/目标、预警 tick、延迟 tick、动作参数、持续时间、终态、重置策略。位置使用引擎整数单位，时间使用 tick；明确边界是否包含以及“进入”判定方式。

默认一次触发、死亡全部重置；默认零预警，触发后迅速执行。循环机关必须显式指定周期和冷却。未解锁的参数不在编辑器展示。

当前设计默认状态机：idle → active → finished。warning 不是通用必经阶段；仅在明确的机关类型需要时添加。零预警是经过定义和测试的策略，不是缺参产生的偶然行为。

确定性执行顺序必须作为版本化协议固定：采样输入 → 应用当前物理规则 → 推进角色及碰撞 → 收集触发事件 → 按机关 ID 排序激活 → 更新机关状态/碰撞 → 死亡判定 → 胜利判定。此顺序为未来引擎设计建议，不能直接替换现有 engine.js 并破坏旧影子。循环引用、重复 ID、越界区域、非法参数在加载时拒绝。

## 5. 如何让机关有用

每关用一句话明确“玩家先相信什么、什么事件打破预期、观察后如何解决”。

- 简单目标：第一眼看得到去哪里，不用先读复杂规则。
- 单一主意：普通关 1 个主要反转，进阶关至多 2 个关联反转；不能用尖刺数量代替设计。
- 让动作触发笑点：玩家跑、跳、落地或接近终点后，场景才回应。
- 第一回意外，第二回可解：同输入必须同结果；不得按死亡次数偷偷更改地图或物理。
- 失败可解释：死亡时短暂标记触发机关和死因；初次卡片不提前揭露所有隐刺。
- 破解靠已知位置的操作：初见直接冲可以立即死亡；重试后必须能在安全边缘试探、提前跳或绕行。不强求每个机关启动后还能凭反应逃脱，也不允许所有可触发位置都必死。
- 重试成本低：死亡表演可跳过，重置无长等待；机关、角色、输入缓冲都恢复一致初态。
- 影子可读：影子与玩家使用相同机关状态机，作者不能享有免疫；视觉特效不参与物理。

机关组合候选（是创作语法，不是已实现关卡）：
1. 接近隐刺 → 提前起跳 → 落到安全区：教会试探。
2. 落石启动 → 停下诱落 → 越过落定方块：奖励观察。
3. 塌地倒计时 → 立即起跳 → 到达真安全平台：制造短促紧张。
4. 弹台起弹 → 调整水平位置 → 抵达上层终点：让辅助道具决定路线。
5. 接近终点 → 终点移位一次 → 改走短支路：未来候选，未实现前禁止生成。

## 6. 评论区 2KB 规则

每张关卡卡片都必须可独立恢复，不依赖另一条评论或发布者手机内的数据。卡片图片单独发送，不占快照预算。JSON 全体（含版本、地图、影子、校验以及未来元数据）按 UTF-8 实测 ≤2048 字节，不是只计算地图大小。

- 同关挑战：保持地图与机关参数不变，只替换经过验证的当前通关影子。
- 改一处回敬：继承地图，改动受限；地图、机关、物理任一改变，必须重新录制通关影子。
- 翻车求助：若未来加入此模式，沿用原有效关卡快照；失败操作不冒充通关证明。
- 只装当前一棒，完整接力历史留给评论文本；不放用户隐私或账号资料。
- 未来机关扩展采用有限枚举与范围受控的整数参数；不允许任意脚本、表达式或网络引用。
- v3 的 tile 编码还有数值空间，但新 tile 的物理语义、触发数据仍需新快照版本；严禁直接复用旧编码改变含义。
- 旧版本必须按其原规则回放；无法兼容时明确拒绝，不把旧影子当有效新记录。

## 7. AI 生成与验收门禁

AI 输入：引擎/快照版本、已支持机关白名单、格子与机关数量限制、可用素材、目标难度、一个主反转。输出：地图、机关参数（仅该版本支持时）、预期触发链、解法说明、求解和快照大小结果。

依次验证：
1. 结构合法：起终点数量、tile、范围、机关引用及数量。
2. 真实可达：当前求解器找到通关输入；超时只能标为“未证明可解”，不能说一定无解。扩展机关后，搜索状态键须包含新增机关的全部相关状态。
3. 回放一致：重置后同一输入多次得到相同状态序列及结束帧；不只比最终胜负。
4. 有效机关：检查主机关是否触发、是否改变路线/时机；绕过机关一直走就能过的地图不能算机关展示关。
5. 编码验证：编码、解码、重新模拟完全一致；非法、越界、超容量快照拒绝；不得静默截断影子。
6. 人工试玩：有预期反转、看得懂死因、重试顺畅；求解器通过不等于有趣。
7. 交付分层：普通浏览器仅做逻辑/模拟检查，最终仍需平台模拟器及 Android/iOS 真机验证。

当前阶段不批量生成关卡、不改变物理。先验证规则，再按小批次扩展。

## 8. 推荐实现优先级（非已完成承诺）

P0：开放已有塌陷地板，补齐机关说明与针对性测试；让现有机关成为必经挑战；优化重试。
P1：建立可版本化的区域触发/一次性延迟协议，优先扩展移动尖刺、移动平台和终点移位；先限低数量。
P2：输入变化、重力、传送、诱饵物；每项先补碰撞、求解器、回放、素材及预算，再开放给 AI 和玩家。

任何阶段不得为了凑到 200 关，跳过机关有效性与人工趣味性筛选。

## 9. v4 触发修正与旧关卡兼容

v4 隐刺不再提前 384 单位触发，而在身体距格子边缘不到 64 单位且脚部进入危险高度时触发。落石不再把左右各一整格当触发范围，改为人物进入石块正下方（左右各内缩 96 单位）后启动。触发不增加随机数，不改变重置规则。

v2/v3 解码后的地图带有规则版本；角色、影子、校验模拟和克隆均使用该版本，重新分享旧关卡也保留原版本。新生成快照用 v4。未升级客户端不能读取 v4，这是显式版本门禁。旧关卡的触发距离保持原样，不冒充新机制。

## 10. 快速试错基线（v6，覆盖此前慢预警建议）

**初见受骗 → 快速死亡 → 记住位置 → 主动引发/提前规避 → 快速通过。**

触发区与伤害区必须分开。已知机关位置的玩家能在危险区外引发机关；不靠慢动画留反应时间，不要求进入致命区中心才触发。盲冲可以被瞬间击中，但知道位置后不能仍被迫死亡。

当前统一配置：
- 落石：距格子外缘 128 整数单位（1/8 格）进入触发范围，立即启动，无抖动等待。初始速度 768 单位/tick，封顶 1024；两格行程约 3 tick。扫掠检测覆盖移动路径及落地那一帧，防止快速穿透或落地漏判。落稳后不继续产生下落伤害。
- 隐刺：低处身体贴近格子外缘 64 单位以内瞬间出现，固定伤害区；高处跳过不触发。记住位置后提前起跳或在边缘诱出。
- 塌地：站上后 4 tick 内消失，无长裂纹警告；观察后从最后稳定边缘起跳。若用于 UGC，必须验证可用路线。
- 固定刺：始终危险，跳跃需要与隐藏机关形成不同节奏。
- 弹簧：落上去立即弹，不作为默认伤害物；落点必须有足够余量。
- 死亡表现：4 tick 命中定格＋12 tick 夸张动作，约 0.27 秒后重生；不自动强制慢回放，可按键跳过动作。

这些是本项目经过程序验证的参数，不声称是 Level Devil 原始数值。旧 v2-v5 快照继续按各自物理规则回放；新快照使用 v6。

每种机关必须成对验收：
1. 盲冲：正常持续前进会在关键处被打断/击中，不能等人过去才发动。
2. 知情破解：边缘试探后停住/退开，或提前跳跃，能稳定通过；不接受只有逐帧刹车的解法。
3. 动作速度：按逻辑 tick 检验，视觉不能慢放掩盖错误碰撞；大位移有扫掠检测。
4. 重试：机制位置与参数不变，每次重置一致；创作者和挑战者规则相同。
5. 组合：每关一个核心骗局，增加组合前先证明单个机关的两条路线；不以重复换皮凑关数。

参考机制分类与证据范围见 [TRAP_MECHANICS_REFERENCE.md](TRAP_MECHANICS_REFERENCE.md)。

## 12. v7 动态坑

第三关使用 SHIFT(9)：宽2格、接近后向左平移2格。第四关使用 CHASE(10)：先在起步段开坑，再连续向右扩大，出口平台保留。两者分别使用字符 m/e；4bit地图编码仍够用。具体参数、布局和验收见 DEMO_LAYOUTS.md。当前编辑器不增加新画笔。

单图最多一个动态坑，位移/扩张覆盖范围必须是完整地基；不支持与该范围中的弹簧、塌地或落石混用。渲染与碰撞共享 left/right/row。求解状态键包含精确边界与状态，克隆独立复制，死亡重置恢复初始坑。v2–v6不能解释新tile，继续保留原规则；新v7快照仍须完整≤2KB并通过回放验证。

第四关的规则是“先跳一次，再持续前进”，不是“直接跑就能过”。必须配对测试只跑死亡、一次普通跳后持续跑通关、相同落地状态停步死亡，不得用求解器任意多跳通关代替该行为验收。

## 13. v8 量化节奏

当前动态坑以 [PACING_MEASUREMENTS.md](PACING_MEASUREMENTS.md) 为准。SHIFT 改为附近真实起跳触发，向右移1格追落点；CHASE 先保留68tick起跳领先，再以跑速1.5倍扩张。旧v7保持左移和24单位慢扩张。不同机关共享可测的操作预算，不共享“必须不停跑”的唯一解法。

## 14. 内容验收优先级

先记录玩家看到的暗示、自然动作、被打破的具体判断、反转发生时刻，再验证可解和参数。标题不能先给答案。自然动作可以中招，也允许玩家预判后首次通过；不强制首死。追赶的短停失败只适用于这类关卡，不能作为整款游戏的统一目标。当前UI与连贯体验问题见 SURPRISE_DESIGN_AUDIT.md，尚未改代码。
