# v17：按支撑碰撞盒与动作时间校准 / 规则 v11

用户要求保持人物大小，调整地图和触发位置，完成可复用的校准并生成手机预览。角色图片、绘制比例、碰撞盒640×800、满速56单位/tick、跳跃参数、固定全图镜头均保留。仅预览，不送审。

## 可复用入口

`engine.js` 导出 `CALIBRATION`、`supportGate(edge,ticks,closingSpeed)` 与 `chaseGate(initialEdge,safeEdge,reserveTicks)`；`levels.js` 导出 `buildRoom({start,exit,traps:[{column,tile}]})`。适用当前12×8地图、1格宽开坑/2格宽移坑/4格宽联动地块与60Hz确定性物理。不是支持任意宽度物理的通用编辑器。

- 不再用人物图片或碰撞盒中心到坑边的距离冒充反应时间。
- 一格坑比人物支撑宽度宽；后沿进入坑口时会完全失去左岸支撑。因此以`world.x`（支撑碰撞盒后沿）作为前进方向基准。
- `supportGate = edge − leadTicks × closingSpeed`。普通开坑用人物满速；迎面移动坑用人物速度与坑边速度之和。阈值固定，不随死亡次数、实时反应或等待偷偷改变。
- 突发类名义领先2tick；第二关用于引导的第一坑领先16tick。领先量不是最终可跳时间，必须实际模拟接地顺序、土狼时间6tick、跳跃缓冲与惯性。
- 追赶速度是人物满速1.5倍。`chaseGate`由坑的初始边界、出口前稳地边界与目标领先量推导启动位置；目标是支撑盒前沿进入稳地时约有10tick跑步距离的领先。实际模拟约9.54tick，含离散取整。
- 终点安全边界从地图的GL列推导，不再把第四关终态固定写死在第9列。联动地块前沿、后坑停止处和触发位置同样由出口与地块宽度推导。
- 第五关联动位移用2tick完成；前后两端同步变化，平台宽度不变。可见坑口与碰撞继续共用精确坐标。

移动机关位置/出口后，使用相同规则和空间路线策略重新验证。若改变基础物理、碰撞盒、坑宽或规则参数，须新建规则版本并重新跑校准矩阵，不能沿用既有通过结论。

## 五关调整

1. 起点右移1格，减少空跑；门前坑在接近失去支撑时揭示。
2. 第一坑仍可看到后再跳；第二坑对准通过第一坑后的继续前进。
3. 保留左移方向；按人物与坑的合拢速度设置启动点，避免坑在远处先移动完。
4. 出口从第10列收至第9列；追赶终态随之收至第8列，启动位置由公式重算。先越小坑，再持续走可以过。
5. 按未来前坑边界标定触发，地块迅速左移，而不是远处慢慢露出坑。

## 验证与范围

`test/v17_calibration_test.js` 对v16真实快照与v17作5关×25种输入延迟×2版本，共250组对照。延迟0代表看到第一变化帧后的下一个tick输入。第二关先按固定路线越第一坑，再对第二坑作延迟输入。

- v16五个被测反转点，在出现后延迟12tick（0.2秒）再跳都能通过。
- v17对应输入延迟12tick都失败；延迟0仍可通过，没有人为禁止及时跳跃或强制第一次死亡。
- v17这五条满速基准路线可通过的延迟范围均为0–6tick；这是测试范围下的结果，不是所有玩家、帧率或走法的统一反应上限。
- 第二关第一坑单独作12tick延迟输入仍能跳过；该路线随后可被第二坑拦住，不冒称整关已通过。
- 30组知情短按跳跃时间变化通关；正常提前跳有宽余量。克隆、重置、快照回放确定性通过。
- 五组另移起点/机关/出口的布局使用同一空间路线策略通关，前四组整体平移后通关tick数保持相同。无需重新手填触发列数。
- v2–v10历史规则保持回放；新快照v11完整112–120字节，低于2048字节。
- 手机尺寸浏览器正常通关与延迟反应失败均逐关对照；不是小红书真机验收。

证据数据见 [v17_calibration_evidence.json](research/v17_calibration_evidence.json)。本次0.2秒基准是本项目的验收条件，不是原作逐帧触发公式；没有声称与原作逐帧一致。
